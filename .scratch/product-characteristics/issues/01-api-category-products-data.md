# Issue 01: API эндпойнт получения данных товаров категории (`categoryProductsData`)

## Проблема
Для работы продуктового воркфлоу требуются данные о товарах конкретной категории, их свойствах (`i_properties`), а также полные тексты нормативных документов (`i_docs_stnd`, `i_docs_rstr`), привязанных к этим товарам. Существующий `server/api/getData/product/[p_alias].js` не загружает тексты документов и работает поштучно, что создало бы оверхед при запросе 30-50 товаров категории.

## Требования к реализации
1. Создать в `site-wsl` эндпойнт `server/api/ai/categoryProductsData/[c_alias].js`.
2. По аналогии с `server/api/ai/categoryData/[c_alias].js`:
   - Находить категорию по `alias`.
   - Если это подкатегория (`parent_id !== 0`), извлекать активные фильтры свойств подкатегории (`catActiveProps`).
   - Получать опубликованные товары категории (`i_products`) с расшифровкой свойств из `i_properties`.
   - Собирать уникальные идентификаторы стандартов (`standart_ids`) и записей Госреестра (`reestr_ids`), привязанных к товарам выборки.
   - Загружать тексты документов с внешнего хранилища `https://chelinstrument.ru/static/doc/parsed/md/${fileName.replace('.pdf', '.md')}`.
3. Формировать ответ с разделением на словарь документов и массив товаров:
   ```json
   {
     "category": { "id": 11, "name": "Уровни", "alias": "urovni", "characteristics": "..." },
     "docs": {
       "stnd": { "12": { "number": "...", "name": "...", "year": 2000, "url": "...", "text": "..." } },
       "rstr": { "45": { "number": "...", "name": "...", "year": 2024, "url_ot": "...", "text_ot": "...", "text_mp": "..." } }
     },
     "products": [
       {
         "id": 140002,
         "name": "...",
         "alias": "...",
         "brand": "...",
         "characteristics": "...",
         "props": { "...": "..." },
         "stndIds": [12],
         "rstrIds": [45]
       }
     ]
   }
   ```
4. Проверить работу эндпойнта на нескольких категориях (с документами и без документов).
