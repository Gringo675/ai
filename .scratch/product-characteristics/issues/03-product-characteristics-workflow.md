# Issue 03: Воркфлоу Mastra `productCharacteristics`

## Проблема
Необходимо собрать и зарегистрировать в Mastra автономный рабочий процесс (`productCharacteristics`), реализующий обработку одного товара по переданному payload, цикл самоисправления копирайтера по замечаниям арбитра и fallback-исследование при отсутствии документов.

## Требования к реализации
1. Создать воркфлоу `src/mastra/workflows/productCharacteristics.ts`.
2. Описать Zod-схемы состояния (`storeSchema`, `productInputSchema`, `outputSchema`).
3. Шаги воркфлоу:
   - `researchFallbackStep`: проверяет наличие документов; если документы отсутствуют или их тексты пусты — вызывает `productCharacteristicsResearcherAgent` для синтеза параметров по названию, бренду и свойствам.
   - `copywriterStep`: генерирует HTML на основе документов (или сводки ресерчера), действующих ТТХ товара, ТТХ категории и замечаний редактора / судьи.
   - `judgeStep`: выполняет аудит сгенерированного HTML на соответствие документам и политике.
   - Цикл `dountil`: объединяет `copywriterStep` и `judgeStep`, повторяет генерацию при вердикте `FAIL` с передачей критики судьи (до 2–3 попыток или до вердикта `PASS`).
4. Терминальное состояние:
   - Если вердикт `PASS` — возвращает итоговый HTML и статус `PASS`.
   - Если вердикт `FAIL` после исчерпания попыток — возвращает последний вариант HTML, статус `FAIL`, подробную критику судьи и список `requiredCorrections` (без фатального падения воркфлоу).
5. Зарегистрировать новый воркфлоу и агентов в `src/mastra/index.ts`.
6. Не запускать `npm run build` или `npm run dev` согласно правилам проекта.
