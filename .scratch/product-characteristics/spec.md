# Спецификация: Генерация характеристик товаров (`productCharacteristics`)

## 1. Назначение и контекст

Система генерации структурированных технических характеристик (`characteristics`) в формате HTML для конкретных позиций товаров (`i_products`) каталога измерительного инструмента на основе:
- Официальных нормативных документов (ГОСТ, ТУ, Описания типа ГРСИ, Методики поверки), привязанных непосредственно к данной позиции;
- Действующих характеристик товара из базы данных (для сохранения специфических каталожных деталей);
- Характеристик родительской категории — **строго и только для товаров без документов** (вместе со сводкой ресерчера Tavily). Если у товара есть официальные документы, характеристики категории копирайтеру не передаются во избежание смешивания обобщенных категорийных данных.

Реализация ориентирована на интерактивный **UI-сценарий** в панели администратора (`AdminPanel`), где оператор выбирает категорию, запускает последовательную генерацию характеристик для товаров категории, визуально сравнивает результаты (Было / Стало), точечно отправляет позиции на доработку с комментариями (ревизия) и сохраняет результат в базу.

## 3. Контракты данных

### 3.1. API бекенда: `/api/ai/productsData/[c_alias]`
Отдает агрегированные данные категории без дублирования текстов документов:
* `category`: `{ id, name, alias, characteristics }`
* `docs`: словарь документов с полными текстами:
  * `stnd`: `{ [id]: { number, name, year, url, text } }`
  * `rstr`: `{ [id]: { number, name, year, url_ot, url_mp, text_ot, text_mp } }`
* `products`: массив товаров категории:
  * `id`: number
  * `name`: string (обогащенное наименование с параметрами)
  * `alias`: string
  * `brand`: string
  * `characteristics`: string (текущие характеристики из БД)
  * `props`: key-value объект каталожных свойств
  * `stndIds`: number[] (ссылки на ключи в `docs.stnd`)
  * `rstrIds`: number[] (ссылки на ключи в `docs.rstr`)

### 3.2. Входная схема воркфлоу Mastra (`productInputSchema`)
```ts
const productInputSchema = z.object({
  product: z.object({
    id: z.number(),
    name: z.string(),
    alias: z.string(),
    brand: z.string().nullable().default(null),
    characteristics: z.string().default(''),
    props: z.record(z.string(), z.any()).default({}),
  }),
  documents: z.array(
    z.object({
      docNumber: z.string(),
      docName: z.string(),
      docType: z.enum(['stnd', 'rstr']),
      fileLink: z.string().nullable(),
      year: z.number(),
      documentText: z.string(),
    })
  ).default([]),
  categoryCharacteristics: z.string().default(''),
  editorFeedback: z.string().optional(),
})
```

## 4. Спецификация агентов и моделей

Все агенты используют модели семейства Flash-Lite через обертку `createGoogleMultiKeyAgent` для обеспечения максимальной скорости работы и минимального расхода квот:
* Основная модель: `google/gemini-3.5-flash-lite` (или `google/gemini-3.1-flash-lite`).
* Fallback-модель: `google/gemini-3.5-flash`.

1. **`productCharacteristicsCopywriterAgent`**:
   * Назначение: Генерация HTML-блока характеристик строго под конкретную позицию.
   * Контекст:
     - Для товаров с документами: документы товара (`documents`), действующие ТТХ товара (`product.characteristics`). Характеристики категории **не передаются**.
     - Для товаров без документов: сводка ресерчера (`fallbackResearch`), характеристики категории (`categoryCharacteristics`), действующие ТТХ товара.
   * Выход: HTML-блок (заголовки с `.doc-viewer-link`, компактная таблица `<table>` с классами `.ta-start` / `.ta-end` / `.ta-center`, текстовые пояснения `<p>`).
2. **`validateProductCharacteristicsHtml` (валидатор разметки и структуры)**:
   * Назначение: Детерминированная кодовая проверка сгенерированного HTML на синтаксическую валидность, структуру тегов и оформление ссылок/документов без галлюцинаций LLM.
   * Проверки:
     - Отсутствие Markdown-разметки (```, `|---|`).
     - Запрет тега `<caption>` и inline-стилей `style="..."`.
     - Баланс и корректное закрытие тегов `<table>`, `<thead>`, `<tbody>`, `<tr>`, `<th>`, `<td>`, `<p>`, `<strong>`, `<a>`, `<ul>`, `<ol>`, `<li>`.
     - Наличие обязательных тегов `<thead>`, `<tbody>`, атрибутов `scope="col"` у `<th>` и классов выравнивания `ta-start` / `ta-end` / `ta-center`.
     - Соответствие порядка документов (ГОСТ/ТУ перед Госреестром СИ) и наличие корректных ссылок `href` с атрибутами `class="doc-viewer-link"` и `target="_blank"`.
   * Выход: `{ verdict: 'PASS' | 'FAIL', reason?: string }`.
3. **`productCharacteristicsResearcherAgent`**:
   * Назначение: Fallback-исследование в сети через Tavily для товаров без документов.
   * Выход: Текстовая техническая сводка параметров конкретной модели.

## 5. Формат характеристик товара (Product Policy)

* **Строгое правило разделения документов:**
  * 1 нормативный документ = 1 отдельный блок и таблица.
  * **Категорический запрет объединения:** разные номера Госреестра СИ запрещено объединять в один заголовок или одну таблицу, даже если они схожи (каждое описание типа имеет свои метрологические спецификации разных лет).
* **Лаконичные заголовки без спама:**
  * `<p><strong>Параметры по <a class="doc-viewer-link" target="_blank" href="...">ГОСТ ...</a></strong></p>`
  * `<p><strong>Параметры по Госреестру <a class="doc-viewer-link" target="_blank" href="...">№ ...</a></strong></p>`
  * Запрещены наименования инструмента, бренда и модели в заголовках.
* **Универсальная 3-уровневая иерархия параметров:**
  1. *Приоритет 1 (Метрологическое ядро):* предел погрешности, отсчет / цена деления, класс точности / разряд, допуски формы (плоскостность, прямолинейность), шероховатость ($Ra, Rz$).
  2. *Приоритет 2 (Конструкция и геометрия SKU):* конкретные размеры (вылет губок целевого товара, длина, масса, футляр). Запрещено указывать диапазоны серии («от 80 до 350 мм»), если у товара есть точный размер («100 мм»). **Однако, если точное значение в данных товара отсутствует, а документ допускает диапазон («80–200 мм»), диапазон сохраняется как есть — выдумывание значений категорически запрещено.**
  3. *Приоритет 3 (Вторичные условия):* климатические условия (температура, влажность) допустимы, но никогда не вытесняют приоритеты 1 и 2.
* **Верстка таблиц:**
  * Тег `<caption>` **не используется** (заголовок оформляется только через `<p><strong>...</strong></p>`).
  * `<table>` с `<thead>`, `<tbody>`, атрибутами `scope="col"` и классами выравнивания `ta-start` (текст), `ta-end` или `ta-center` (числа/значения).
  * Запрещены inline-стили `style="..."` и markdown-таблицы.
* **Характеристики категории:** Использовать **исключительно** как вспомогательный контекст при отсутствии документов у товара. При наличии нормативных документов категории в промпт копирайтера не включаются.
